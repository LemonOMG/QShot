### 探针抓到的真缺陷：描边笔骑在路径上

边框原本是 1px 描边笔画 `drawRect(rect().adjusted(0,0,-1,-1))`。**描边笔以路径为中心向两侧各铺半笔宽**，所以 DPR 2 时右边缘有半笔（= 1 设备像素）落进图像里，把内容最后一列染成 `#FF0000A5`。

验算对上了：255 × (1 − 90/255) = **165**，正是 alpha 90 的黑覆盖在纯蓝 (0,0,255) 上的结果。已改成**四条填充色带**（`fillRect`），填充矩形是精确的逻辑矩形，在任何整数 DPR 下都落在整设备像素上。

顺带把边框宽度从 **1 改成 2 逻辑像素**：DPR 1.5 时 1px 边框让内容起点落在设备坐标 1.5 上，**整幅图被平移半像素并重采样**；2px 在 DPR 1 / 1.5 / 2 下都落在整数设备像素上（2×1.5 = 3，2×2 = 4）。`kBorderWidth` 的注释里写了这个理由。

### 另一个真问题：`qRound` 在正负坐标下不对称

`anchoredTopLeft` 第一版按**绝对位置**取整：`C' = qRound(anchor - u*newScale)`。平移不变性断言直接失败 —— 整体平移 `(0,-1080)` 时结果差了 1px。原因是 `qRound` 对 .5 的处理：正值向 +∞（`int(d+0.5)`），负值远离零（`int(d-0.5)`）。同一手势在原点为负的屏幕上会落在不同的像素上。

改为按**位移**取整：`C' = C + qRound((anchor - C) * (1 - newScale/oldScale))`。位移在整体平移下不变，所以结果精确同步平移；而且 12 次放大 + 12 次缩小后仍**精确回到原位**（这条断言在两种写法下都通过，说明位移写法没有引入漂移）。

# 第二段：贴图的悬停提示样式（用户反馈）

用户原话：「贴图我觉得可以加入一些鼠标移入的样式，例如内阴影+右上方关闭图标，**不然截最大化窗口时用户都不知道底下是一张图片**。」

这个反馈点中一个真实的可用性死角：贴图最常见的用法就是把**最大化窗口**的截图钉在屏幕上，此时贴图与它底下的窗口逐像素相同、且覆盖整个屏幕 —— 屏幕上没有任何东西能告诉用户「你看到的是一张静止图片」，更不知道该怎么关掉它。原设计里唯一的提示是 2px 边框变色，而不悬停时它是 `#818181` 中灰，识别度太低。

## 落地内容

`src/pin/PinWindow.h/.cpp`（106+210 → **139+362**）：

| 元素 | 参数 |
| --- | --- |
| 内阴影 | 深 14 逻辑像素，边缘 alpha 150，**二次衰减**（14 条同心 1px 色带） |
| 关闭按钮 | 右上角 18×18、距内容边 3px；深色圆盘（静止 140 / 悬停 205）+ 白色圆头 X |

新增公开访问器 `contentRect()` / `closeButtonRect()`（后者**放不下时返回空矩形**），私有 `drawInnerShadow()` / `drawCloseButton()` / `chromeVisible()`，新状态 `closeHovered_`。

三个刻意的决定：

1. **色带互不重叠**：横向条与纵向条拼成「口」字形（纵向条跳过横向条已占的首末行）。两条半透明填充叠在同一像素会让**四角比四边暗一倍** —— 手写内阴影最典型的破绽。
2. **衰减而不是实心内嵌矩形**：实心矩形读起来是「第二条粗边框」。
3. **太小就不画按钮**：需要 18 + 2×3 = 24 逻辑像素，放不下时返回空矩形，点击**穿透到拖拽**。返回被裁切的矩形会画出压扁的 X，像渲染 bug。

## 顺带修掉的真缺陷：贴图一直在漏

`ShotApplication::onPinRequested()` 的注释写着「It is created with `WA_DeleteOnClose`」，但 `PinWindow` 的构造函数里**从来没设过这个属性**，别处也没有 —— 即**每关一张贴图就漏掉一个窗口 + 它持有的 QImage**（全屏约 16MB）。加了关闭按钮之后 `close()` 从「Esc / 双击 / 右键菜单」变成**鼠标一键可达的主路径**，漏的概率大增，所以一并补上，且放在构造函数里当不变量。

> ⚠️ 副作用：**不能对栈上的 `PinWindow` 调用 `close()`** —— 延迟 `delete this` 打在栈对象上。生产代码全堆分配；探针里凡测 `close()` 的一律堆分配 + `QPointer`，并用 `pin.isNull()` 断言「真被回收，不只是隐藏」。

## 踩到的坑：探针把逻辑坐标当设备像素索引

第一版穷举比对直接用**逻辑**控件坐标去 `QImage::pixel()`，而 `pixel()` 索引的是**设备**像素。DPR 1.5 下采样范围**恰好落进了阴影窄带本身**，于是报出 **2059 个「差异像素」** —— 全是阴影在正常工作。修法：一切按 dpr 换算，允许不同的区域也要按 dpr 取整（阴影深 14 逻辑像素在 DPR 1.5 下要留 `qCeil(14×1.5)=21` 设备像素边），并且给按钮排除区留 2 设备像素余量（抗锯齿覆盖会溢出逻辑矩形一点点）。

另有两处是**探针自己的期望值写错**：① 拿纯色图的 `240` 去断言坐标编码图的像素；② 断言 idle 边框 alpha == 120 —— 实际是 255，因为 `QWidget::render()` 默认带 `DrawWindowBackground`，会先用调色板背景铺满，边框的 alpha 混的是**调色板**而不是桌面（贴图是不透明窗口）。这条值得记住：**贴图边框的 alpha 不会透出底下的桌面**。

# 第三段：M4 历史记录

## 做了什么

**`src/core/HistoryStore.h/.cpp`**（496 行）：截图历史的落盘与淘汰。单例 `instance()`，同时开放构造函数注入目录与字节预算，测试才好写。

- 全图写 PNG 到 `QStandardPaths::AppDataLocation/history/<id>.png`，**缩略图也落盘**（`<id>.t.png`）。原计划「内存只留缩略图」，但缩略图不落盘会导致启动时要解码 20 张全图才能出菜单。
- 条数（默认 20）+ 总字节（默认 200MB）双预算，超限删最旧**连文件一起删**；字节预算**永不驱逐最新一条**（否则一张超大图会让历史直接空掉）。
- 索引 `index.json` 用 `QSaveFile` 原子写。**索引损坏不删图**：解析失败当空历史重建，绝不动磁盘上的截图。
- 用户另存的文件是**拷贝进来**（不是引用）且是**文件级拷贝不是重新编码**：前者保证用户清理「图片」文件夹不会把历史清空，后者保证 JPEG 的既有有损质量不被二次损失。为此 `ImageExport::saveImageWithDialog` 返回值由 `bool` 改成 `QString`。

**`src/ui/HistoryMenu.h/.cpp`**（230 行）：托盘「历史记录」子菜单，每项带缩略图。

- 每条是**子菜单**（不是「动作挂 submenu」—— Qt 会把那种动作渲染成只有子菜单、本体不可触发）。
- 菜单用 `aboutToShow` 重建，不维护平行副本。
- **动作按条目 `id` 闭包捕获，不按行号**。这是抓到的真 bug：行号在删掉一条之后整体前移，「先删一条再复制另一条」是极普通的操作序列，按行号会静默复制错条目。

**设置**三项：`history/enabled`、`history/limit`（1–200，默认 20）、`history/notifyOnCopy`。`setHistoryLimit()` **故意不触发驱逐** —— 对话框的「取消」要是真取消，收缩留到下次 `add()`/`load()`。新增文案 15 条（47 → 62）。

## 踩到的坑（都值得记住）

**① 探针 exe 的 `exit=127` 且毫无输出 = DLL 没找到，不是文件不存在。**
Windows loader 在 `main()` 之前就失败，Git Bash 把它报成 `127`，与「命令不存在」完全一样。我为此连续误判三轮。修法：运行前把 `D:/Qt/6.11.2/mingw_64/bin` 与 MinGW 的 `bin` 加进 `PATH`。

**② 编辑正在运行的 bash 脚本会报出无关的语法错。**
bash 按字节偏移边读边执行，改动让它从错位处继续解析，于是报 `line 133: syntax error near unexpected token '('` —— 而那一行 `echo "$failures probe(s) failed to build"` 本身完全合法。看到「刚改过的脚本在运行中报语法错」应先重跑，不要去找那个不存在的 bug。

**③ 工厂必须整组链接。**
`PlatformFactory.cpp` 点名四个 Windows 实现，而**每个实现的 vtable 在自己的 TU 里发出**，只链调用到的那一个仍会缺符号（`undefined reference to vtable for qshot::WinAutoStart`）。库也一样：`-ldwmapi -lgdi32 -luser32` 要跟着平台组走（detector 要 DWM，capturer 要 GDI 的 `CreateCompatibleDC/SelectObject/DeleteObject`，hotkey 要 user32）。

**④ `C:/...` 能当编译参数，不能当命令。**
MinGW 要 `cygpath -m` 的混合形式，而 bash **exec** 不了它（`exit=127`）。执行要用 `cygpath -u`。脚本里因此同时维护 `OUT`（给编译器）与 `OUT_SH`（给 bash）。

`build-review/build_probes.sh` 现在支持 `--run`：无名字时一键「全建 + 全跑」。13 个目标的源文件组合与 moc 依赖写在脚本内的注册表里，**moc 按类名 glob 定位、绝不写 hash 目录**（CMake 一重跑 hash 就变）。运行阶段自动把 Qt/MinGW 的 `bin` 加进 `PATH`，并从 `build-review/` 执行（渲染脚手架互相读 PNG 当 fixture）。

# 第四段：M5 序号 / 高亮标注

## 先推翻了一个「前置约束」

上一段把「工具栏 6 → 8 个按钮，小选区下会溢出屏幕」列为 M5 必须先解决的阻塞项。**实测下来这个约束不存在，而且估算本身就是错的**：

- 原估「4 个动作按钮」，实际 M3 已经加了 `Pin`，是 **5 个**。
- 工具栏是**顶层窗口**，不隶属于选区；`updatePosition()` 把它钳制在**屏幕**矩形内，与选区大小无关。所以真正的问题是「装不装得进屏幕」，不是「装不装得进选区」。
- 实测（`probe_toolbar_layout.cpp`）：6 工具宽 **412px**，8 工具宽 **484px**。本机逻辑屏 1707px ⇒ **余量 1223px**；1366px 小屏 ⇒ 仍有 **882px**。

所以**没有**做两排布局，也没做「更多」溢出菜单 —— 那会为一个不存在的问题改动所有人的工具栏。改成把不变量写成断言：任何选区下摆放后的工具栏必须完全落在给定屏幕矩形内（含四角 1×1 选区、以及原点是 `(1920,0)` 的第二块屏 —— 后者正是「拿 0 当屏幕边缘」会出错的地方）。

**教训**：计划里写的「必须先想清楚的约束」也要先实测再动手。这条约束让上一轮特意留着没做 M5，结果是假的。

## 做了什么

- `AnnotationType` 加 `Number`、`Highlight`；`Annotation` 加 `int number` 与 `int badgeDiameter`。
- **序号**：点击落一个自动递增的圆徽标，按住可微调，松手提交。计数器 `SnapOverlay::nextNumber_` 在**重新画选区**时重置；移动/缩放既有选区**不**重置（那些标注还在，编号必须保持一致）。
- **高亮**：荧光笔自由涂抹，复用 `points`。
- 工具栏 8 个工具 + 分隔线 + 5 个动作 = 484px；两个新图标都是 2px 描边几何画法。
- 新增 `defaultToolSettings(AnnotationType)` 提供按工具的出厂默认色。

## 四个偏差（都写进 ROADMAP 了）

**① 高亮只做自由涂抹，没做「半透明矩形」。** 矩形高亮与现有矩形工具几乎是一回事（只差填充），而自由涂抹没有替代品。若日后要补，正确做法是给矩形工具加「填充」开关，不是新开工具。

**② 端点用 `FlatCap` 而不是 `SquareCap`。** 第一版用 `SquareCap`，探针立刻抓到：**方帽在两端各多伸出半个笔宽**（默认 18px 宽 ⇒ 每端 9px）。沿一行文字拖过去，左右各糊 9px 到页边距上 —— 而「对齐一行文字」正是这工具的主要用法。改 `FlatCap` 后严格止于拖拽两端。代价：**零长度线段在 `FlatCap` 下没有面积**，单击什么都画不出来，所以单点单独画一个半径 = 半笔宽的圆点（也正是真实荧光笔点在纸上的样子）。

**③ 颜色存储必须用 `HexArgb`。** 高亮的全部身份就是 alpha（默认 110），而 `Settings::setToolSettings()` 原本存 `color.name()` = `HexRgb`，**会把 alpha 丢掉** —— 存一次重启一次，荧光笔就变成不透明黄。这是个会静默损坏数据的 bug。`QColor::fromString()` 两种格式都认，老配置仍读得进来。

**④ 出厂默认色按工具区分。** 原来 `ToolSettings` 只有一个共享默认（橙）。新增 `defaultToolSettings()` 让首跑默认 / `restoreDefaults()` / 「配置只写了一半」三条路径由同一函数产出。顺带修掉：关掉「记住工具设置」时 `toolSettings()` 原本返回裸 `ToolSettings()`（橙），现返回该工具自己的默认色。

## 一个真 bug：撤销会永久留空号

序号在**按下时**占用（这样拖动时徽标能显示编号），**提交时**才消费。撤销若只把标注从图层删掉，`nextNumber_` 继续往前跑 —— 撤销掉 3 号再落一个得到 4 号，中间的空号用户再也填不上。因此 `AnnotationLayer::undo()` 改为**返回被删掉的类型**，`handleUndo()` 见到 `Number` 就把号还回去。右键取消落点天然不消费（提交才消费），无需额外处理。

### 探针失败全部是期望值写错（第 3 轮，产品无 bug）

- `QIcon::pixmap(16,16)` 的参数是**逻辑**尺寸，而 Qt 6 里 `QPixmap::size()` 报的是**设备**像素（逻辑走 `deviceIndependentSize()`），dpr 1.5 下要 16 得到 24×24。

### 1. 工具栏真图标集（已完成，**不是 SVG，是代码绘制**）

原计划写的是「SVG + `QIcon`」，实际走的是**代码绘制**：新增 `src/overlay/ToolbarIcons.{h,cpp}`，`bool paintTool(QPainter&, AnnotationType, const QRect&, const QColor&)`。返回 `bool` 是为了让调用方区分「工具」和「动作/分隔符」，后者回落到动作文案 —— `ToolbarWidget::drawButton` 里那条约 70 行的 if-else 链和 `iconName` 参数整段消失。

- **抓到两个真读错的形状**：① **画笔**原本是裸斜线 = 去掉箭头的箭头；改成两段 `quadTo` 的波浪。② **马赛克**原本是两个方块，读起来是「复制/重叠」；改成 3×3 棋盘格（只填 `(row+col)` 为偶的格，`x1 = left + ((col+1)*side)/3` 保证三格之和正好等于边长）。

### 2. 部署裁剪：一条**已经过期**的理由

`tools/deploy.sh` 保留 `Qt6Svg` + `iconengines/qsvgicon` 的注释写的是「下一步要换成 SVG 工具栏图标」。这一步走了代码绘制，**那条理由变成假的** —— 一条写错的注释比两种选择里的任何一种都糟，于是把整组删掉：`Qt6Svg.dll` 632KB + `qsvgicon.dll` 75KB + `qsvg.dll` 40KB + `qgif.dll` 49KB。**理由是攻击面不是体积** —— 从不打开图片文件的截图工具不该带一个 632KB 的 XML/SVG 解析器。

删之前先把「应用到底用什么格式」实测了一遍：支持的格式是 `bmp cur ico jfif jpeg jpg pbm pgm png ppm xbm xpm`，其中**只有 `cur`/`ico`/`jfif`/`jpeg`/`jpg` 来自 `imageformats/`**，其余全是 QtGui 内置 —— 这正是「少一个也不报错」的原因。留下 `qico`（托盘图标是嵌入的 `.ico`，走 `QImageReader` 读，缺了只是图标变空白）+ `qjpeg`（`.jpg` 是 ImageExport 两种格式之一）。

**插件是运行期按名字加载的，导入闭环结构上看不见它们** —— 这是静态校验唯一覆盖不到的一类部署错误。所以 `probe_deploy.cpp` 新增第 `[4]` 节，**双向**断言：缺 `ico`/`jpeg` 要失败，`svg`/`gif` **回来了**也要失败。后者才是让裁剪清单成为「一个决定」而不是「会悄悄漂移的东西」。

**反向断言特意验证过它不是空转**：把三个插件临时拷回暂存目录 → 两条 `FAIL`、`probe exit=1`；清掉后恢复 `10/0`。**一条永远不会失败的检查比没有检查更糟**（`verify_iss.py` 上已经吃过一次同样的教训）。

结果：**11 个 PE 文件 / 102 个导入全解析 / 1 个翻译文件 / 34MB**（裁剪前 15 / 124 / 35MB）。

## 第七段：M6 设置补项 —— 静默保存 / 复制时同时保存

两个新开关，**都默认关闭**（打开任何一个都会改变用户的文件出现在哪里，而开始写没人要的文件的截图工具比每次都问的更糟）。

### 范围收窄（这里最容易做错）

- `save/quiet` 只作用于**截图工具栏的保存按钮**。图钉右键菜单与历史菜单里那两项是**另存为** —— 「另存为」的全部含义就是自己挑位置，静默它等于让用户再也没法把某张放到别处。这两条继续走 `saveImageWithDialog()`。
- `save/onCopy` 只作用于**正在截的这一张**，不含从历史菜单重新复制一张（那个文件第一次截取时就写过了，再写只会把保存目录填满同一张的副本）。

### `saveImageQuietly(image, parent, directory)`

- 名字 `screenshot_<yyyy-MM-dd_HH-mm-ss>.<ext>`，扩展名跟随 `save/format`。**同名绝不覆盖**，后缀递增到 `_2`…`_999`；上界是必要的，目录不可写时 `exists()` 会一直说谎，无界循环会挂住应用。目录不存在则 `mkpath`。
- **第三个参数是目录覆盖**，空的才读设置 —— 存在的唯一理由是探针：真实目录是用户数据，测试绝不能写进去。
- 失败**必须出声**：`parent` 非空时弹 `QMessageBox`；`parent` 为空不弹（调用方自己报，或探针不能阻塞在模态框上）。
- **抽出 `writeImage()`**：两条保存路径对「格式从哪来」看法不同（对话框看用户敲的扩展名，静默路径看设置），但**编码本身不能不同**，否则同一张图「另存为 .jpg」和「静默存 JPEG」产出不一样的文件。判断 `.jpg`/`.jpeg` 的地方现在只有一处。同理抽了 `resolvedSaveDirectory()`。
- 反馈：静默保存成功弹托盘气泡 `已保存到：<路径>`（**不看**「复制后弹托盘提示」开关 —— 对话框没了之后气泡是唯一证据）；复制时同时保存成功换成 `已复制，并保存到：<路径>`（一个说两件事的气泡好过两个各说一件的）。

### 接线

`SnapOverlay::captureCopied()` → `captureCopied(const QString& savedPath)`（空是常态不是错误）；新增 `captureSaved(const QString&)` 只由静默路径发出。`HistoryMenu::copied()` 保持无参，在 `ShotApplication` 用 lambda 接成 `onCaptureCopied(QString())`，理由写在 lambda 旁边。

### 验证 `probe_quiet_save` 29/0

名字模式正则锚定 / **强制制造同名碰撞**（先种一个文件占住当前秒的名字，再断言后缀递增且原文件一个字节没动；循环最多 3 次并要求「碰撞路径确实被走到」，否则这条检查会时灵时不灵）/ 目录按需创建 / PNG 无损往返 + `.jpg` 真的是 JPEG 且真的有损 / 历史记录**采用**该文件而非重新编码（断言后缀保留 + 删掉用户原文件后条目仍可读）/ 空图像不写任何东西 / **探针改过的设置被放回**（独立读 `QSettings` 复核）。

### N-7 马赛克增量包围盒 —— 探针抓到一个**既有** bug

`updateMosaic()` 改成接收 `logicalDirty`（空 = 整条标注，给 `rebuildMosaicCache()` 用）。`probe_mosaic_incremental.cpp` 第一次跑就报两种喂法差 **314 个整块**。

根因：`p.translate(-logicalBounding.topLeft())` 用的是**未裁剪**的逻辑原点，而掩码图从 `physicalBounding.topLeft()`（**已和图像求交**）开始。两者只在没裁剪时重合；触到选区边缘的笔画，掩码原点被裁进去多少，整幅马赛克就被推出去多少。左上角点一下，马赛克被推到对角一个块外。**这是既有 bug**（旧的整路径调用同样会裁剪），N-7 的探针把它照出来了。

修法：`p.translate(-physicalBounding.x() / dpr_, -physicalBounding.y() / dpr_)` —— 除以 dpr 精确，且没裁剪时退化成原表达式。

结果 **10/0**：240 点 / 600×450 物理图，**整路径 98ms → 增量 7ms**，两幅图逐像素相同。新增第 `[5]` 节断言「左上角点一下，马赛克包围盒恰好一块 `(0,0)-(11,11)`」—— 这条 bug 的最小复现。

### 探针：`probe_partial_repaint`（23 号，119 checks / 0 failures）

核心断言**不是**「脏区等于我手算的矩形」（那只是把被测公式抄进测试，公式错了照样绿），而是：

> **只重绘脏区之后的整帧，与整帧全量重绘逐像素相同。**

再配「屏幕远端角落不在脏区里」把「正确」升级成「正确**且**确实变小了」；另加两条**负向对照**（故意给过小的区域必须报出差异、把 `targetOffset` 传成 `(0,0)` 必须让画面位移）保证这套比较**有能力失败**。

### 踩到的两个坑（都是探针的，不是产品的）

**一、`QWidget::render(target, targetOffset, sourceRegion)` 的语义。** 探针第一版用 `render(&target, QPoint(0,0), QRegion(dirty))` 原地重绘，结果每一步报 10 万+ 差异像素，而且**差异框尺寸恰好等于脏区尺寸、位置在原点**。这个形状指向坐标位移而不是绘制内容 —— 于是写了个 30 行最小程序定论：

```
part   @ (0,0)=red    @ (100,50)=black
=> the region's content landed at the ORIGIN
```

**`targetOffset` 是「源区域的内容」落点，不是「控件原点」落点。** 原地重绘要传 `region.topLeft()`。探针现在把这个语义**显式断言**（连反例一起）。已写进 skill `qt-gui-verification` 的 `references/qt-semantics.md`。

**二、hover 定时器污染测量窗口。** overlay 有个 30ms 单次 `hoverTimer_`，由 Idle 下的鼠标移动启动，它一次 `update()` 会把被悬停窗口的轮廓画出来 —— 表现和「脏区算错了」一模一样（差异框 672×512 对着 264×204 的脏区，而 672×512 正是被枚举到的**真实窗口**）。两处修正：`drain()` **不再在两次 `processEvents()` 之间 sleep**（那正是 30ms 定时器插进来的窗口），以及把 Idle 那一步挪到**最后**。已写进 skill。

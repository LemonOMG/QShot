### 三个真实发现

### 踩到的坑（都实测过）

- ⚠️ **`PASS_REGULAR_EXPRESSION` 不能加 `^...$`**：CTest 对**整段**输出做一次匹配、不是逐行。

### 真正的病灶：`credential-helper-selector` 垫片

`GIT_TRACE=1 GIT_CURL_VERBOSE=1` 抓到的时序（`/tmp/push_trace.log`）：

```
15:57:36  <= Recv header: HTTP/1.1 401 Unauthorized      # 正常，首次请求就是要凭据
15:57:36  <= Recv header: www-authenticate: Basic realm="GitHub"
15:57:36  run_command: 'git credential-helper-selector get'
15:57:36  built-in: git config --system -e               # ← -e = 编辑，会拉起编辑器
15:57:37  run_command: echo .../PortableGit/.../etc/gitconfig
          ─────── 72 秒空白 ───────
15:58:49  run_command: '".../git-credential-wincred.exe" get'
```

`git config --system -e` 是**编辑**系统 gitconfig，会拉起一个编辑器；非交互 shell 里没人应答，
就挂在那儿。（这一步是从追踪推断的，没有直接抓到编辑器进程 —— 但那 72 秒空白只能是它。）
72 秒后它自己退出，才轮到真正的 wincred，而此时我的超时已经把它杀掉。

**关键事实：凭据一直都在。** 直接问 wincred（密码打码，不进对话）：

```
$ printf 'protocol=https\nhost=github.com\n\n' | git-credential-wincred.exe get
username=LemonOMG
password=<REDACTED>
```

### 绕开的办法

`credential.helper` 是列表属性，**空值会清空整个列表**，所以可以只保留 wincred：

```bash
git -c credential.helper= \
    -c credential.helper='!"C:/Users/18791/.workbuddy-ai/binaries/PortableGit/versions/1.2.0/mingw64/bin/git-credential-wincred.exe"' \
    push --progress github master
```

**立刻成功。** 没有改任何持久配置 —— `-c` 只作用于这一次命令。

### 刻意没有做的

- 没有 `git config --global` 覆盖 `credential.helper`。那样能让以后每次 push 都快，
  但那是改用户环境，该由用户决定。
- 没有 `http.schannelCheckRevoke=false`（09-23 拒绝了，今天仍然拒绝）。
- 没有 `--force` / `-u`：确认过远端在 `c908199`（= 本地父提交），是快进。
